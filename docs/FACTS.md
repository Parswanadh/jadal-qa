# FACTS for the explainer (as of 2026-10-10 ~16:30 IST). Use ONLY these numbers. Anything marked PENDING must be shown as "in progress", never as a result.

## Direction (decided by the builder today)
- Edge-first: Awign's mentors said they record the videos themselves, decentralised is fine if it runs on a Raspberry Pi, rejection reasons are generic, accept/reject can be fully automated with no mandatory human. Not yet measured on a Pi (only x86 laptop cores as a proxy). A real Pi run is pending.
- Whole-video, per-pixel analysis of EVERY frame (not 4-8 sampled frames). Streaming: analyse 2-second chunks while the worker records, early reject (dark/blocked/frozen) in the first 1-2 s.
- Deterministic, mathematics-first decisions: measured signals (noise level, sharpness, exposure, frame-difference vs the noise floor, residual motion after removing camera motion, rhythm tests) + a transparent rule list with exact thresholds; logistic regression/boosted trees are only comparison baselines. Every reject carries evidence (value, comparison, threshold). Receipts are content-hashed (SHA-256 of canonical JSON), not signed.
- A generic VLM was tried and STOPPED by the builder: too probabilistic. Interim numbers (SmolVLM2-2.2B, 8 frames per 10 s, n=79 labels, 14 bad): yes/no answer AUROC 0.57, probability score AUROC 0.77 (not reliable at n=14), ~1.4 s per segment => about 58 days of GPU time for 3.6 million 10-s segments (10,000 hours).
- EmbeddingGemma 2 is now an optional feature extractor/search tool (hub, dedup), not the core. Laya (text-only) and Clef (hosted) are not in the pipeline.
- "Hyperspectral": the cameras are RGB (3 bands). Recovering a spectrum from RGB is under-determined (metamerism); literature check found no evidence it helps these tasks. We do per-pixel frequency/temporal-spectral analysis of RGB, NOT hyperspectral imaging. A hyperspectral sensor would be needed for real spectral data.
- "Optical thermodynamics": literal meaning (photon gas in multimode fibres) is irrelevant to a head camera. The useful physics is sensor physics and information measures: Poisson-Gaussian noise model (SNR), H.264 bits per frame, frame difference vs noise floor, noise-normalised sharpness, residual optical flow, exposure clipping, histogram entropy, dHash. Heat-equation blur, colour temperature, MSCN, max-entropy: dropped (relabelling or low value).

## Measured results so far (all leave-one-clip-out on the 150 human labels unless stated; clip-bootstrap 95% CI)
- GPU-side per-pixel feature set (27 features, mostly temporal) + logistic head: AUROC 0.80 (0.71-0.87). Early-reject cascade: ~2% exit at stage 0 (dark/black/frozen caught 6/6 each on synthetic), 50% accepted at stage 1, 18% rejected at stage 1, 30% uncertain (hand to the expensive tier). On the 70% decided windows: balanced accuracy 0.81; 8 of the 75 good decided windows were falsely rejected; 8 of the 30 bad decided windows were accepted. NOT yet "high accuracy" — improvement work in progress.
- Temporal-only features: AUROC 0.71. Inverse-PCA colour residual adds nothing (0.793 with vs 0.794 without). Skin/rPPG/illumination features alone do not transfer across clips (AUROC < 0.5).
- Other arms on the 150 labels (harness, partial): OpenCV+MediaPipe signals on 4 frames 0.46; same signals on all frames 0.68; EmbeddingGemma-2 head 0.60. Spectral arm B was scored on only an old 79-label snapshot (0.64-0.68, CI spans 0.5): stale, re-run pending.
- Duplicates (64 constructed pairs, held-out half): spectral signature F1 0.947, EmbeddingGemma-2 cosine 0.909, pHash 0.865 (small n: differences not established). Not yet tested on the 6 real human DUPLICATE labels (in progress).
- Funnel calibration on the real signals: with 150 labels NO L0 rule can be statistically certified (the multiple-testing correction needs ~86 clean fires; the certification split has 84). Descriptively TOO_DARK catches 6/6 at 1 false alarm. So error rates are reported as observed, not as certified bounds.
- Speed (single core, this laptop, NOT a Pi): full H.264 480p decode ~90-100x real time (3 clips); keyframe-only decode ~200x; spectral arm B total 24x (T0, 64px) / 19x (T1, 160px) incl. decode, 217x/57x for the math alone. GPU kernels alone 1,800-2,000 hours of video per hour; one CPU core ~22 h/h. NVDEC (GPU decode) is NOT faster than CPU decode for a single 480p stream (2,348 vs 2,820 fps); this chip has one NVDEC engine. END-TO-END GPU number: PENDING.
- Target: 10,000 hours in 1-2 h = 5,000x aggregate real time (3,333x at 3 h) => with arm B on CPU about 209 (T0) / 263 (T1) cores; moving 4.5-9 TB (at 1-2 Mbps, an estimate) is likely the bottleneck. Live streaming at the device needs only 1x real time. The builder's own goal is NOT to process 10,000 hours on one GPU, but to find the limits of one GPU and show the optimisations (an optimisation ladder, in progress) that scale to deployments.
- Hardware: RTX 4070 LAPTOP GPU, 36 SMs = 4,608 CUDA cores, 8 GiB VRAM, ~256 GB/s theoretical memory bandwidth, PCIe 4.0 x8 (measured host-to-GPU 5.7-7.6 GB/s). Power limit fixed at 80 W by firmware (140 W max not changeable from Linux); thermally limited (CPU ~97 C, GPU 85-90 C under load).
- Determinism: CPU feature path gives an identical quantised digest over 10 repeated runs; GPU numerics are not claimed identical across devices. Cross-architecture determinism is not claimed. Real-module end-to-end proof (10 identical receipt hashes) PENDING.
- Receipts: SHA-256 of canonical JSON; re-verify = re-run the pinned pipeline on the original clip and compare; tampered receipt fails; not cryptographically signed (optional HMAC sidecar).

## Pipeline as designed now
1. Stage 0 (first 1-2 s, tiny resolution): exact rules, reject dark/blocked/over-exposed/frozen immediately with evidence.
2. Stage 1 (whole video, every frame at reduced resolution, streaming accumulators): per-pixel spatial spectrum, temporal spectrum, noise model, motion after camera-motion removal -> rule list + score.
3. Stage 2 (only uncertain windows): heavier tools (MediaPipe hands, EmbeddingGemma-2) — optional.
4. Receipt (hash) + dashboard; humans only audit samples. Quality features are measured on RAW pixels; activity features on CLEANED video (denoise/normalise/motion-compensate); each cleaning step must earn its place in cross-validation. Label-noise audit flags suspicious labels (never edits the human's).

## UPDATE 2026-10-10 18:25 IST — interpretation correction (supersedes any 'hand-region motion is the signal' wording)
- The DeepSeek-harness rhythm model (PR #77) is a documented NEGATIVE result: LOCO AUROC 0.753 (0.65-0.81) vs 0.810 for the 26 per-pixel features; synthetic negatives made it 0.351 on real windows (it learned the fakery).
- Its analysis found that residual-motion MAGNITUDE scalars are INVERTED on the real windows (good windows show LESS residual flow; signed AUROC ~0.20, i.e. 0.80 oriented) because its ego-motion compensation is translation-only and walking/turning leaves residual motion everywhere. So the strongest motion cue behaves like 'the wearer is not walking' rather than 'work is happening'.
