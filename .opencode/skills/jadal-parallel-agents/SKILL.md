name: jadal-parallel-agents
description: How to run many agents in parallel in opencode v2 on the pod: subagents via the task tool (several calls in one message), headless worker processes per git worktree, concurrency limits, file-ownership rules, failure handling. Load before launching more than one task.
license: Apache-2.0
---
**A. Subagents (inside one session).** Call the `task` tool several times IN ONE MESSAGE for independent tasks (e.g. 4 `experimenter` calls on E1, E2, E6, E8 + a `docs` call). Each brief must be self-contained (goal, inputs with absolute paths, output folder, id prefix in the registry, deadline, return format <= 120 words) and the output folders must be DISJOINT. Do not give two subagents the same file. Subagents cannot launch subagents here (`task: deny` for them).
**B. Headless workers (separate processes, survive the lead).** `bash tools/pod/launch_workers.sh start <name> <agent> <prompt-file>` creates a worktree + branch and runs `opencode run --auto --standalone --agent <agent> -m "$JADAL_MODEL" --title <name> "$(cat <prompt-file>)"` in the background (own private server, log in `/workspace/logs/<name>.log`, PID recorded); `status` lists them; `stop <name>` kills ONLY the recorded PID. Concurrency cap: `JADAL_MAX_WORKERS` (default 4). Always verify tool activity in the log after 60 s; a log that only contains help text means the flags are wrong for this opencode version.
**C. Verify the CLI first.** `opencode --version`; `opencode run --help` (v2.0.x flags: `--agent`, `-m provider/model#variant`, `--session/-s`, `--continue`, `--fork`, `--format json`, `--file`, `--title`, `--auto`, `--standalone`, `--server`; there is NO `--dir`/`--variant`: use `cd <worktree>` and `#variant` in the model string); `opencode debug agents` must list lead/experimenter/explorer/reviewer/tester/docs/infra; `opencode debug config` must show this repo's `opencode.json`; load a skill once to confirm the `skill` tool lists the `jadal-*` skills.
**D. Rules.** Never exceed the GPU/CPU budgets in `jadal-pod-resources`. The lead reads result FILES, not chat summaries. A failed subagent is relaunched with a narrower brief and the failure is logged in `docs/pod/RUNBOOK.md`. Never let two workers push the same branch.
